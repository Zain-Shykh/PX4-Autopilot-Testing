## Attitude estimator

`src/modules/attitude_estimator_q/attitude_estimator_q_main.cpp` defines the class and implementation in one file. The meaningful analyzed behavior includes initialization from gravity and magnetic vectors, quaternion propagation, heading-source choice, acceleration correction, gyro-bias learning/clamping, declination rotation, parameter updates, message validation, velocity differentiation, attitude publication, and synchronous `Run()` routing. Startup freshness checking is also exercised. CLI help/entry-point and dynamic task-allocation wrappers remain visible in the full-file coverage denominator but are outside the numerical/message-processing claim.

The estimator is nontrivial because history, sensor validity, configured gains, freshness thresholds, and normalized vectors interact. Important state includes `_initialized`, `_data_good`, `_ext_hdg_good`, `_q`, gyro/bias/rates, previous IMU and velocity timestamps, velocity history, and position acceleration. Inputs arrive through `sensor_combined`, `vehicle_magnetometer`, `vehicle_gps_position`, visual/mocap odometry, and local position; output is `vehicle_attitude`. Parameters control correction weights, heading mode, acceleration compensation, declination, magnetometer availability, and the intended bias bound.

**PX4 functional GTest** is appropriate: its existing runner initializes uORB and the parameter subsystem. The work distribution proposed unit tests, but actual dependencies warrant the functional level permitted by the assignment. Tests publish real local messages, control parameter storage or cached values as appropriate, and call the actual implementation. They do not duplicate its algorithms in a fake estimator. A link-time `hrt_absolute_time` replacement supplies exact timestamps in this executable only. Parameter autosave is disabled because the functional runner does not start a scheduler. Retained samples are drained for independent fixtures; shuffled repetitions passed.

The only production edit is a `friend class AttitudeEstimatorQTestPeer` declaration plus its explanatory comment. No method, branch, threshold, or parameter behavior was altered. Because the class has no header, the test includes the production `.cpp` once and links its supporting libraries, not the module library, avoiding duplicate definitions. CMake registers `functional-AttitudeEstimatorQ` and confines the clock substitution to that target.

## Hysteresis

`src/lib/hysteresis/hysteresis.cpp` implements the ordinary `systemlib::Hysteresis` class (not a template). Its requested/actual Boolean states, last request timestamp, and separate rising/falling delays determine whether a transition is pending, canceled, or due. This is meaningful shared state logic used by PX4 modules.

**PX4 unit GTest** is sufficient: time is already an explicit method argument and there are no message/parameter dependencies. The existing seven upstream tests remain unchanged. Seven new tests in `HysteresisAssignmentTest.cpp` focus on exact deadlines, cancellation at the deadline, live duration changes during a pending transition, timestamp zero, independent objects, and the largest non-overflowing timestamp. This makes the contribution distinguishable even though upstream tests already cover every instrumented line.
