## Measurement and contribution

All three reports use GCC `--coverage` at `-O0` with LCOV **branch coverage explicitly enabled**. Zero-count `.gcno` data is merged with execution counters, so untouched production files are not omitted. `GCOV_PREFIX` stores each phase separately; existing build counters cannot inflate these reports. Only the two production `.cpp` files enter the denominator. Test source, generated parameter code, and math-library headers are not added to it.

The **baseline** is focused upstream-only execution (`unit-Hysteresis`), not a whole-repository coverage run and not Member 2's existing coverage. It was captured before new tests ran and recaptured with the final translation-unit instrumentation for a comparable denominator. No student tests execute in that phase. It shows hysteresis **22/22 lines (100%), 17/20 branches (85%)** and estimator **0/225 lines, 0/556 branches**. See [baseline HTML](coverage/baseline/html/index.html).

The **student-only** run and **final** run produce the same scoped hits: hysteresis **22/22 lines (100%), 17/20 branches (85%)**; estimator **199/225 lines (88.4%), 347/556 branches (62.4%)**. Combined: **221/247 lines (89.5%), 364/576 branches (63.2%)**. The final run includes upstream hysteresis tests in addition to Member 1's suites. See [student HTML](coverage/student/html/index.html), [final HTML](coverage/final/html/index.html), [final LCOV](coverage/final/coverage.info), and [summary JSON](coverage/summary.json).

The estimator's core `Run()` through `update_mag_declination()` methods (source lines 201–587, including all sensor/message validation and filter computation) execute **184/184 instrumented lines**. This is a labeled sub-scope observation, not a replacement for the full-file denominator or a 100% branch claim. Line coverage is the gcov approximation for statement coverage; it is not a separate count of every C++ statement. Hysteresis receives additional boundary/state evidence, not a fictitious improvement over its already-complete upstream line coverage.

## Every remaining gap

[uncovered_obligations.csv](coverage/uncovered_obligations.csv) lists **all 26 unexecuted lines and all 212 unexecuted LCOV branch edges**, including exact source line, block/edge identity, source expression, explanation, and needed strategy. No edge is removed from the raw percentages.

- **Hysteresis: three edges at lines 77 and 83.** Entry requires `requested != state`, allowing only `(true,false)` or `(false,true)`. If the first directional test fails, the second necessarily succeeds. This makes one short-circuit edge at line 77 and two at line 83 infeasible for valid Boolean state. All feasible transitions and elapsed/not-elapsed results execute. Corrupting a `bool` representation would be undefined behavior, not a legitimate additional test.
- **Estimator callback registration: lines 193–195.** Registration succeeds with initialized local uORB. Its false branch, error log, and return need a controlled callback registration/allocation failure. Their two missed lines and associated call/control edges remain counted. Full allocator fault injection is not provided by this fixture.
- **Estimator nested message-copy guards: lines 229, 245, 263, 339, 372.** `updated()` checks availability without advancing this subscription's generation; the subsequent `update()` consumes it. With a stable manager and single consumer, `updated()==true` followed by `update()==false` is not produced. Concurrency/topic teardown or a subscription-failure seam would be needed; no blanket “hardware dependent” justification is used.
- **Quaternion magnitude checks: line 455.** After successful finite normalization, length is approximately one. Degenerate inputs cover the nonfinite rejection, but the finite-and-`<=0.95` and finite-and-`>=1.05` outcomes do not arise from the tested construction. Injecting a fault in normalization or pausing between normalization and validation would test these defensive paths. Numerical fault injection is outside this unchanged production implementation.
- **CLI/task wrappers: lines 589–640.** Twenty-four unexecuted lines and sixteen branch edges belong to custom command/help output, entry point, dynamic module allocation, and task-spawn cleanup. The assignment excludes trivial wrappers from the assessed business/control scope; they nevertheless remain visible in the full-file figures. Separate module lifecycle and allocation-failure tests would cover them.
- **Compiler exception edges:** 184 further unexecuted edges within non-wrapper code are labeled exception edges (`e` blocks) by LCOV. Successful C++ calls take their normal paths; no dependency throws. Testing these edges would require exception injection, and they are not independent source-level decisions. Retaining them explains much of the difference between source-path coverage and the raw GCC branch percentage.

The estimator's functional tests emit work-queue “not running” diagnostics because PX4's standard functional runner initializes parameters/uORB without scheduler threads. Assertions and process exits pass; synchronous `Run()` and direct method calls are intentional. No scheduling, concurrent publisher teardown, Gazebo flight, hardware, or whole-autopilot safety claim follows from these results.
